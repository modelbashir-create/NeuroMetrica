# NeuroMetrica Workspace Architecture 2.1 (Current)

This document is the source of truth for structure, MVVM boundaries, and file responsibilities.
It is written to be AI-agent friendly: explicit trees, per-file roles, and clear ownership rules.

Guiding rules
- Strict MVVM in the app target: Views depend on ViewModels and state, never on engine or IO.
- Apple HIG aligned UI structure and behavior.
- Clear layering: App -> Core -> Features -> Engine Packages.
- Core services hide engine, file IO, and logging details from Features.
- Packages provide imaging IO/engine (ChromaImagingCore, ChromaEngineKit) and ML runtime (RedEngine).
- Launch screen is static (UIKit-only); loading screen is app-owned UI.

3) App Responsibilities (Per File)

App/
- NeuroMetricaApp.swift
  - App entry point. Creates the WindowGroup and hosts AppContainer.
- AppContainer.swift
  - Composition root for UI + dependency injection.
  - Creates ViewerState, AppSettings, services, and ViewModels.
  - Chooses between the Loading flow and the main Viewer UI at startup.
  - Owns loading gate and ensures loading screen only shows once per app launch.
- LaunchScreen.storyboard
  - Static launch screen (UIKit-only, no animation). Mirrors first-frame branding.

Core/Models/
- AppSettings.swift
  - Global preferences (window/level defaults, backend prefs, UI flags).
  - Observable shared settings; future persistence target.
- AppError.swift
  - App-level error wrapper for user-facing error descriptions.
- Study.swift
  - Study model used by sidebar and recents list.
- StudySeries.swift
  - Series model used by sidebar and recents list.

Core/Protocols/
- VolumeOpenRouting.swift
  - Cross-feature protocol used by Import to request Viewer volume loading.

Core/Services/Logging/
- AppLogger.swift
  - Centralized OSLog-based logging for app actions and errors.

Core/Services/FileSystem/
- FilePickerService.swift
  - Abstraction for file selection and URL normalization.
- RecentFilesStore.swift
  - In-memory recents store for the Import sidebar; future persistence target.

Core/Services/Imaging/
- ChromaEngineBridge.swift
  - Primary boundary between app ViewModels and engine packages.
  - Loads volumes, creates slices, hides ITK/Metal details.

Core/Utils/Extensions/
- ViewNeuroMetrica.swift

7) MVVM Boundaries (Quick Reference)

- Views:
  - Live under Features/*/Views.
  - Read state from ViewModels or ViewerState.
  - Never import ChromaEngineKit or ChromaImagingCore directly.
- ViewModels:
  - Live under Features/*/ViewModels.
  - Own business logic and call Core services (ChromaEngineBridge, FilePickerService, RecentFilesStore).
- Models:
  - Live under Core/Models or Features/*/Models.
  - Represent app or feature domain state and DTOs.
- Core Services:
  - Live under Core/Services; hide engine and IO details.
- Packages:
  - Provide the imaging and ML substrate; app does not depend on their internals directly.
